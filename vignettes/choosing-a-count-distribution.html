Choosing a count distribution

flexCountReg fits the same regression model with many count distributions. This vignette shows a workflow for choosing among them: fit candidate families, compare their fit statistics, and check how well each one reproduces the observed counts.

library(flexCountReg)
data("washington_roads")

The washington_roads data contain crashes on 507 road segments observed over three years. We model total crashes as a function of traffic volume (lnaadt) and the speed-limit indicator speed50, with segment length as an exposure offset.

Fitting candidate families

countreg() takes the distribution as family. Gradient-based optimizers (method = "BFGS" or "NR") are usually the fastest choice for the closed-form families.

f <- Total_crashes ~ lnaadt + speed50
fit <- function(family) {
  countreg(f, data = washington_roads, family = family, offset = "lnlength",
           method = "BFGS")
}
models <- list(
  Poisson = fit("Poisson"),
  NB1 = fit("NB1"),
  NB2 = fit("NB2"),
  PIG1 = fit("PIG1"),
  GP1 = fit("GP1")
)

Comparing fit statistics

glance() gives one row of fit statistics per model, so the candidates can be compared side by side.

do.call(rbind, lapply(names(models), function(nm) {
  cbind(model = nm, glance(models[[nm]])[, c("logLik", "AIC", "BIC", "df")])
}))

McFadden’s pseudo R-squared compares each model with the same baseline, an intercept-only Poisson model (the base count model), so the values are comparable across distributions. A different baseline can be chosen with the basemodel and variables arguments of regCompTable() and regCompTest().

Does the model reproduce the counts?

Information criteria rank models, but they do not show where a model fails. A rootogram compares the observed frequency of each count with the frequency expected under the fitted model, on a square-root scale. Bars hang from the expected curve; a bar that ends above zero means the count is over-predicted, one that ends below zero means it is under-predicted.

oldpar <- par(mfrow = c(1, 2))
rootogram(models$Poisson, main = "Poisson")
rootogram(models$NB2, main = "NB2")

par(oldpar)

The Poisson model under-predicts zeros and large counts, the typical signature of overdispersion. NB2 tracks the observed frequencies closely.

Randomized quantile residuals are standard normal when the model is correct, for any count distribution, so a normal Q-Q plot is a useful check:

set.seed(1)
oldpar <- par(mfrow = c(1, 2))
for (nm in c("Poisson", "NB2")) {
  r <- residuals(models[[nm]], type = "quantile")
  qqnorm(r, main = nm, pch = 20, col = "grey40")
  abline(0, 1, col = "firebrick")
}

par(oldpar)

A CURE plot (cumulative residuals against fitted values or a covariate) is another standard diagnostic in safety analysis:

cureplot(models$NB2, indvar = "lnaadt", n_resamples = 20)

Modeling the dispersion and the zeros

The distribution parameters can depend on covariates. Here the NB2 dispersion depends on the speed-limit indicator:

When there are more zeros than a count distribution allows, a zero-inflated or hurdle version of any family can be fitted with zero_formula:

zinb <- countreg(f, data = washington_roads, family = "NB2",
                 offset = "lnlength", zero_formula = ~ 1, method = "NR")

# Estimated probability of a structural zero

#> [1] 0.004677454

Here the probability of a structural zero is estimated at essentially zero and the log-likelihood equals that of NB2: the zeros are already explained by the negative binomial, so the zero-inflated model adds nothing. (When an estimate is at the boundary like this, its standard error is not meaningful.)

Using the chosen model

Predictions have one value per row of new data. Besides the expected count, predict() gives the probability of each count:

nd <- washington_roads[1:3, ]
predict(models$NB2, newdata = nd)
#> [1] 0.7961933 0.7036126 1.1665157
round(predict(models$NB2, newdata = nd, type = "prob", max_count = 4), 3)
