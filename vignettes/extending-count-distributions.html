Adding a count distribution to flexCountReg

This article is for contributors. It explains what a new count distribution has to provide for it to work throughout flexCountReg, by tracing the existing NB2 family through the source code. Code that uses flexCountReg::: reaches internal objects: they are shown here to explain the implementation, may change between versions, and are not part of the user-facing interface. Users only see the family argument of countreg() and countreg_rp() and the exported distribution functions (ddpo(), pdpo() and so on).

library(flexCountReg)

1. Define the distribution first

Before writing code, state for the new family:

  • its support (here, the counts \(0, 1, 2, \dots\));
  • its natural parameters and their spaces;
  • how the regression enters: in flexCountReg the mean model is \(\mu = \exp(X\beta)\) (times an offset), and each distribution parameter is \(\exp(W\delta)\) of its own linear predictor, or a logistic function of it for a probability (labels such as ln(alpha) and logit(rho) show the scale);
  • whether \(\mu\) is the actual mean. It is for NB2. For the Poisson-lognormal family the mean is \(\mu \exp(\sigma^2/2)\); for the generalized Poisson with negative dispersion \(\mu\) is a location parameter; for the double Poisson, hyper-Poisson, gamma count and discrete Weibull families flexCountReg solves numerically for the natural parameter that makes the mean equal to \(\mu\).

These choices decide how coefficients are interpreted, so they belong in the documentation (?count_families) as well as in the code.

3. The regression family entry

Every family that countreg() and countreg_rp() can use has one entry in the internal list .fcr_family_registry, built with .fcr_family(). The NB2 entry:

nb2 <- flexCountReg:::.fcr_family_registry$NB2
names(nb2)
#> [1] "params"   "dens"     "variance" "rand"     "mean_adj" "start"    "mean"    
#> [8] "cdf"      "start_rp"
nb2$params
#> [[1]]
#> [1] "ln(alpha)"
#> 
#> [[2]]
#> NULL
names(formals(nb2$dens))
#> [1] "y"         "predicted" "alpha"     "sigma"     "..."       "log"
body(nb2$dens)
#> .fcr_quiet_dens(stats::dnbinom(y, size = 1/alpha, mu = predicted, 
#>     log = log), log)

The fields (documented at the top of R/families.R):

Field Meaning
params labels of the (up to two) distribution parameters, which are also the coefficient names; NULL for none
dens function(y, predicted, alpha, sigma, ..., log): \(P(Y = y)\) given the mean parameter predicted and the distribution parameters on their natural scale; returns probability 0 (or -Inf) outside the parameter space, without warnings, because the optimizer tries such values
variance variance at mean parameter \(\mu\) (Pearson residuals, documentation tests)
rand random draws (simulate(), parametric bootstrap)
cdf optional log CDF or log survival function, computed directly (quantile residuals, intervals); without it the PMF is summed
mean, mean_adj the mean when it is not \(\mu\)
start, start_rp starting values of the distribution parameters (on the linear-predictor scale) for countreg() and countreg_rp()

The registry density must agree with an independent calculation:

y <- 0:6
all.equal(nb2$dens(y, predicted = 2.5, alpha = 0.4, sigma = NULL),
          dnbinom(y, size = 1 / 0.4, mu = 2.5))
#> [1] TRUE

4. Public distribution functions

A family is more than a likelihood: users need its d/p/q/r functions. The families added in 0.1.2 implement four small internal functions and pass them to shared wrappers in R/count_dist_utils.R, which give every distribution the argument conventions of base R: recycling, zero-length inputs, NA and NaN, NaN with a warning for invalid parameters, probability 0 with a warning for non-integer x, lower.tail and log.p. For the double Poisson:

body(ddpo)
#> {
#>     .fcr_d(x, list(lambda = lambda, phi = phi), .dpo_valid, .dpo_logpmf, 
#>         log)
#> }
body(qdpo)
#> {
#>     .fcr_q(p, list(lambda = lambda, phi = phi), .dpo_valid, .dpo_logcdf, 
#>         .dpo_qstart, lower.tail, log.p)
#> }
  • .dpo_valid() says which parameter values are in the parameter space;
  • .dpo_logpmf() returns \(\log P(Y = y)\), computed on the log scale;
  • .dpo_logcdf() returns \(\log P(Y \le y)\) or \(\log P(Y > y)\), each computed directly, so that tiny upper-tail probabilities keep their relative precision (never as \(1 - P(Y \le y)\));
  • .dpo_qstart() gives a rough starting point for the quantile search.

The contract can be checked numerically. For the Delaporte distribution:

mu <- 3; rho <- 0.4; k <- 2
x <- 0:200
p <- ddelaporte(x, mu = mu, rho = rho, k = k)
c(total = sum(p),
  mean = sum(x * p),
  cdf_matches_pmf = isTRUE(all.equal(cumsum(p)[1:20],
                                     pdelaporte(0:19, mu, rho, k))),
  log_tail_direct = pdelaporte(150, mu, rho, k, lower.tail = FALSE,
                               log.p = TRUE))
#>           total            mean cdf_matches_pmf log_tail_direct 
#>          1.0000          3.0000          1.0000       -140.5794
# a quantile is the smallest count whose CDF reaches the probability
q <- qdelaporte(0.9, mu, rho, k)
c(q = q, cdf_q = pdelaporte(q, mu, rho, k),
  cdf_q_minus_1 = pdelaporte(q - 1, mu, rho, k))
#>             q         cdf_q cdf_q_minus_1 
#>     6.0000000     0.9493058     0.8967050
# invalid parameters and non-integer counts
suppressWarnings(c(ddelaporte(2, mu = -1, rho = rho, k = k),
                   ddelaporte(2.5, mu = mu, rho = rho, k = k)))
#> [1] NaN   0

The log upper tail at 150 is finite, where \(1 - P(Y \le 150)\) would be 0 in floating point.

5. Through a fitted model

Once registered, the family is used by every part of countreg():

set.seed(4)
d <- data.frame(x = rnorm(300))
d$y <- rnbinom(300, size = 2, mu = exp(0.5 + 0.4 * d$x))
fit <- countreg(y ~ x, data = d, family = "NB2", method = "BFGS")
mu_hat <- predict(fit)
alpha_hat <- exp(coef(fit)[["ln(alpha)"]])
# predict(type = "prob") uses the registry density
all.equal(unname(predict(fit, type = "prob", max_count = 3)[1, ]),
          nb2$dens(0:3, predicted = mu_hat[1], alpha = alpha_hat,
                   sigma = NULL))
#> [1] TRUE
# simulate() uses the registry's random draws
sims <- simulate(fit, nsim = 4000, seed = 1)
c(mean_ratio = mean(rowMeans(sims) / mu_hat),
  var_ratio = mean(apply(sims, 1, var) /
                     nb2$variance(mu_hat, alpha_hat, NULL)))
#> mean_ratio  var_ratio 
#>  0.9999219  0.9997107
# quantile residuals use the cdf hook
summary(residuals(fit, type = "quantile"))
#>      Min.   1st Qu.    Median      Mean   3rd Qu.      Max. 
#> -3.314260 -0.650915 -0.022552  0.006811  0.665310  2.549137

Offsets, weights, the rows used in the fit, and the alignment of predictions with newdata are handled by the shared data preparation, not by the family. A new family needs no code for them, but its tests should include a model with an offset.

6. Capabilities are opt-in

A registry entry makes a family available in countreg() (including zero models, which are built from dens) and in countreg_rp(). Other features are enabled explicitly, because each depends on a mathematical property that must be established for the family:

  • Underreporting requires that binomial thinning of the family is the same family, with known parameters (.fcr_thinning_families, .fcr_thin_params()); the reported-count variance law is tested for each listed family.
  • Likelihood-ratio tests against Poisson or another family require a nesting and its type: an interior restriction (ordinary chi-square) or a boundary one (a mixture of chi-squares). Families are listed in .fcr_family_nesting only when the restriction is regular.
  • Analytic gradients exist only for Poisson, NB1 and NB2; other families use numerical derivatives.
  • Moment starting values for the dispersion exist for NB1, NB2, PIG1, PIG2 and PIG (.fcr_moment_disp_start()); other families use start.
  • Exact random-parameter predictions use the moment-generating function of the random parameter and the family’s mean adjustment, so mean_adj and mean must be right.

Diagnostics follow the same contract: Pearson residuals need variance, quantile residuals and rootograms need dens and preferably cdf, and marginal effects need the mean.

Finite mixtures and latent classes (countreg_mix(), countreg_lc()) use the same registry entry for each component: the log-scale dens for the likelihood and posterior class probabilities, mean (or mean_adj) for component and mixture expected counts, variance for the mixture variance and Pearson residuals, cdf (or a summed PMF) for the mixture distribution function and quantile residuals, and rand for simulate(). A new family therefore works as a mixture component as soon as its entry is complete, but it is reported as experimental until it is added to .fcr_fm_validated together with tests: one-component agreement with countreg(), an independently coded two-component likelihood, and a recovery study such as inst/validation/finite-mixtures/mixture-recovery-study.R. Because a registry dens returns probability 0 (-Inf on the log scale) for an invalid parameter value, as countreg() needs, the mixture engine cannot tell such a value from a count with probability zero by the density alone. It therefore checks the component parameters itself and rejects a candidate whose parameters are not finite and positive, or whose density raises an error, before it enters the likelihood.

7. Tests

At least four kinds of tests are needed:

  1. Special cases against independent implementations, for example NB2 with \(\alpha \to 0\) against dpois(), or a parameter value that gives a geometric distribution.
  2. The distribution contract: probabilities sum to 1, the CDF equals the summed PMF, quantiles are the smallest count reaching the probability, random draws match the probabilities, base-R argument handling, large means and extreme parameters stay finite.
  3. Registry agreement: the registry density and CDF equal the public functions at the regression parameterization, and the variance equals the summed second moment.
  4. Estimation and prediction: countreg() recovers the parameters of simulated data, and predict(), simulate() and the residuals agree with the registry.

A small recovery test, in the form used in tests/testthat/:

testthat::test_that("countreg() recovers NB2 parameters", {
  set.seed(11)
  n <- 4000
  d <- data.frame(x = rnorm(n), t = runif(n, 0.5, 2))
  d$y <- rnbinom(n, size = 1 / 0.5, mu = d$t * exp(0.5 + 0.4 * d$x))
  m <- countreg(y ~ x + offset(log(t)), data = d, family = "NB2",
                method = "BFGS")
  testthat::expect_true(m$model$converged)
  est <- coef(m)
  se <- summary(m)$coefficients[, 2]
  truth <- c(0.5, 0.4, log(0.5))
  # within four standard errors: fails rarely by chance, often if wrong
  testthat::expect_true(all(abs(est - truth) < 4 * se))
})
#> Test passed with 2 successes 🥇.

Tests involving random numbers set a seed and use tolerances justified by the standard errors, not tolerances tuned until the test passes.
