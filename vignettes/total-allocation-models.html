Total-plus-allocation models: counts by severity

Crash counts often come in categories at each site. The categories can be:

  • ordered, such as severity levels: property damage only (PDO), injury and fatal crashes;
  • unordered, such as crash types: animal, rollover and other crashes, or collision types, or vehicle types.

One way to model them is to describe two things:

  • how many crashes happen (the total);
  • how they split across the categories.

countreg_alloc() fits both parts jointly. The total follows any count family of the package, and each part has its own covariates. The split follows an ordered probit or ordered logit model for ordered categories (sections 1 to 4), or a multinomial logit model for unordered ones (section 5).

library(flexCountReg)
data("washington_roads")
w <- washington_roads
w$pdo <- w$Total_crashes - w$Injury_crashes - w$Fatal_crashes
w$injury <- w$Injury_crashes
w$fatal <- w$Fatal_crashes
colSums(w[, c("pdo", "injury", "fatal")])
#>    pdo injury  fatal 
#>    633     57      5

1. The model

For a site with category counts \(y_1, \dots, y_J\) and total \(c = \sum_j y_j\):

\[ P(y_1, \dots, y_J) = P(c) \times \frac{c!}{\prod_j y_j!} \prod_j \pi_j^{y_j}. \]

\(P(c)\) is the count model of the total, here NB2 with mean \(\mu = \exp(x'\beta)\). The \(\pi_j\) are the allocation probabilities. For severity levels, ordered from the least to the most severe, an ordered probit gives them from a latent severity propensity \(z'\gamma\) and thresholds \(\psi_k\):

\[ \pi_j = \Phi(\psi_j - z'\gamma) - \Phi(\psi_{j-1} - z'\gamma). \]

m <- countreg_alloc(cbind(pdo, injury, fatal) ~ lnaadt + speed50 +
                      offset(lnlength),
                    alloc_formula = ~ lnaadt + speed50,
                    data = w, family = "NB2")
summary(m)

A positive allocation coefficient shifts crashes toward the more severe categories.

The thresholds are \(\psi_1\) (Threshold1) and the log of the gap \(\psi_2 - \psi_1\) (Threshold2). This keeps them in order.

2. Zero totals are part of the model

Most segment-years have no crashes. Such a segment-year contributes \(P(c = 0)\) to the likelihood and nothing about the split, since there are no crashes to split. The total is not truncated at one: zeros are ordinary observations of the count model.

Data sometimes hold only units with at least one crash by construction, for example when they are built from crash records. There the total should follow the zero-truncated distribution \(P(c) / (1 - P(0))\), which truncated = TRUE gives. Fitting such data without it biases the count model, and countreg_alloc() says so when the data have no zero totals:

pos <- w[w$Total_crashes > 0, ]
f <- cbind(pdo, injury, fatal) ~ lnaadt + speed50 + offset(lnlength)
mt <- countreg_alloc(f, alloc_formula = ~ lnaadt + speed50, data = pos,
                     family = "NB2", truncated = TRUE)
mn <- countreg_alloc(f, alloc_formula = ~ lnaadt + speed50, data = pos,
                     family = "NB2")
#> No unit has a zero total. If the data hold only units with at least one event by construction, use `truncated = TRUE`; otherwise the untruncated total is right.
se <- function(x) sqrt(diag(vcov(x)))[1:4]
round(rbind(all_rows = coef(m)[1:4], se = se(m),
            positive_truncated = coef(mt)[1:4], se = se(mt),
            positive_not_truncated = coef(mn)[1:4]), 3)
#>                        (Intercept) lnaadt speed50 ln(alpha)
#> all_rows                    -8.896  1.124  -0.568    -0.913
#> se                           0.446  0.051   0.110     0.228
#> positive_truncated         -10.945  1.342  -0.162    -0.946
#> se                           1.092  0.120   0.196     0.462
#> positive_not_truncated      -3.491  0.569  -0.072    -3.509

On the 400 segment-years with crashes, the truncated fit estimates the same count model as the fit on all rows, but from much less information: its standard errors are more than twice as large, because the zeros carried information too, and its estimates differ from the full fit by up to about two of those standard errors. The untruncated fit on the same rows is badly biased: it mistakes the missing zeros for a much higher crash rate and almost no overdispersion.

The expected totals of a truncated fit are those of the untruncated distribution. type = "total_positive" (or conditional = TRUE for the category counts) gives the expected count given at least one crash.

3. Predictions

predict() returns the expected count in each category, \(E[c]\,\pi_j\), by default. type = "prob" gives the probabilities \(\pi_j\), and type = "total" gives the expected total:

predict(m, newdata = nd)

simulate() draws new category counts: a total from the count model, then its split from the multinomial distribution.

4. Generalized thresholds

threshold_formula lets the thresholds depend on covariates, so a variable can change the shares of the middle categories differently from the extremes:

mg <- countreg_alloc(cbind(pdo, injury, fatal) ~ lnaadt + speed50 +
                       offset(lnlength), alloc_formula = ~ lnaadt,
                     threshold_formula = ~ speed50, data = w,
                     family = "NB2")
AIC(m, mg)
#>    df      AIC
#> m   8 2567.414
#> mg  9 2568.491

5. Unordered categories: counts by crash type

Crash types have no order: an animal crash is not “more” than a rollover. For such categories, link = "mnl" splits the total with a multinomial logit:

\[ \pi_j = \frac{\exp(z'\delta_j)}{\sum_k \exp(z'\delta_k)}, \qquad \delta_1 = 0. \]

The first column of cbind() is the base category. Every other category has its own coefficients \(\delta_j\), so a variable can shift crashes toward one type and away from another. The order of the other columns does not matter, and a different base gives the same fit with coefficients relative to that base.

washington_roads counts animal and rollover crashes; the rest of the total are other crashes:

w$other <- w$Total_crashes - w$Animal - w$Rollover
colSums(w[, c("other", "Animal", "Rollover")])

#>      587       85       23

It is negative: busier segments have more crashes in total, but a smaller share of them are rollovers. The animal-crash share falls with traffic too, but that evidence is weak (p about 0.06). How does this compare with a separate count model for each type?

  • With a Poisson total and the count model’s covariates in alloc_formula, the model is the same as independent Poisson regressions of each type, with the same log-likelihood.
  • With an overdispersed total (such as NB2), the types share the total’s unobserved heterogeneity: a segment with more crashes than expected has more of every type. Separate NB models cannot capture that.
  • The split has its own covariates, so a variable can affect how many crashes happen without changing their mix, or the reverse.

The multinomial logit assumes independence of irrelevant alternatives: the ratio of the shares of two types does not depend on the other types. Random parameters in rpar_alloc (section 8) relax this. They give each category but the first its own random coefficients, a mixed logit split. The other options also work with link = "mnl": truncated, tv(), likelihood = "fractional" and the shared site-year term (section 9), which gets a loading for each category but the first. The threshold options (threshold_formula, rpar_threshold, shared_in = "threshold") apply only to the ordered links.

6. Multinomial or fractional likelihood

The default likelihood raises each \(\pi_j\) to the category count \(y_j\). That makes it a proper likelihood of the category counts, so likelihood-ratio tests, AIC and BIC are valid.

Shabab et al. (2026) instead raise \(\pi_j\) to the observed share \(y_j / c\). Then a site-year with one crash carries the same weight in the split as one with a hundred. likelihood = "fractional" gives that version. It is a quasi-likelihood, so:

  • standard errors come from the sandwich, clustered by group_var when it is given;
  • AIC, BIC and likelihood-ratio tests are not available.
mf <- countreg_alloc(cbind(pdo, injury, fatal) ~ lnaadt + speed50 +
                       offset(lnlength), alloc_formula = ~ lnaadt + speed50,
                     data = w, family = "NB2", likelihood = "fractional",
                     group_var = "ID")
cbind(multinomial = coef(m), fractional = coef(mf))

8. Random parameters

Sites differ in ways the covariates do not capture: some have more crashes than their traffic and speed limit predict, and some have more severe crashes. rpar_total and rpar_alloc add random parameters to the total and to the severity propensity. With group_var = "ID", each road segment gets one draw of its random parameters, shared by its three years. correlation = "across" lets the two be correlated:

mr <- countreg_alloc(cbind(pdo, injury, fatal) ~ lnaadt + speed50 +
                       offset(lnlength), alloc_formula = ~ lnaadt + speed50,
                     data = w, family = "POISSON", group_var = "ID",
                     rpar_total = ~ 1, rpar_alloc = ~ 1,
                     correlation = "across", rpar_draws = 200, seed = 1)

The random intercepts fit much better than the NB2 model without them. The segment effect on the total (a Poisson-lognormal total) takes over the role of the NB2 overdispersion. The negative correlation says that segments with more crashes than their covariates predict tend to have relatively less severe crashes.

The likelihood is simulated: each segment’s likelihood is averaged over rpar_draws draws of its random parameters (randomly shifted Halton points), with analytic gradients. rpar_threshold adds a random term to the gaps between thresholds, which changes the share of the middle categories. Random slopes are more terms in the same formulas, such as rpar_total = ~ 1 + lnaadt.

Predictions for a new segment average over the random parameters (random = "marginal", the default). For a segment in the estimation data, random = "posterior" uses its own crash history (Empirical Bayes):

nd <- w[w$ID == w$ID[1], ]
round(cbind(predict(mr, newdata = nd),
            predict(mr, newdata = nd, random = "posterior")), 3)
#>        pdo injury fatal   pdo injury fatal
#> 1    0.754  0.028 0.001 0.535  0.025 0.001
#> 502  0.750  0.028 0.001 0.532  0.025 0.001

9. A shared site-year term

Random parameters drawn per segment are shared by all its years. A segment-year can also have its own unobserved conditions (a wet winter, roadwork) that change both how many crashes happen that year and how severe they are. shared_formula adds one standard normal draw \(u_{it}\) per row to the equations in shared_in, each with its own loading \(s_{it}'\kappa_e\):

\[ \log \mu_{it} = x_{it}'\beta + \lambda_{\text{total},it}\, u_{it}, \qquad z_{it}'\gamma + \lambda_{\text{alloc},it}\, u_{it}. \]

This is the term \(\eta_{it}\) of Shabab et al. (2026). They use one loading for all equations, which makes the correlation positive. With a loading for each equation the correlation has the sign of \(\lambda_{\text{total}} \lambda_{\text{alloc}}\). Changing the signs of all loadings gives the same model, so only their relative sign is identified.

ms <- countreg_alloc(cbind(pdo, injury, fatal) ~ lnaadt + speed50 +
                       offset(lnlength), alloc_formula = ~ lnaadt + speed50,
                     data = w, family = "POISSON", shared_formula = ~ 1)

The loading in the total plays the role of the NB2 overdispersion (a Poisson total with this term alone is the Poisson-lognormal model), and the fit is as good as the NB2 model. The loading in the propensity has the opposite sign, but it is not significant: these data show no clear year-to-year link between a segment’s crash count and its severity split.

shared_formula = ~ lnaadt would let the loadings depend on traffic, and shared_in can include "threshold". The integral over \(u_{it}\) uses adaptive Gauss-Hermite quadrature (shared_nodes, centred on each row), and countreg_alloc() warns when doubling the nodes changes the log-likelihood noticeably. With random parameters, the quadrature runs inside each draw of the segment’s parameters, which multiplies the cost of the fit by the number of nodes.

Reference
